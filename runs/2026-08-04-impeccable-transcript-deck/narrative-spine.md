# Narrative spine

## Audience promise

Explain how Impeccable 4.0 turns taste from an after-the-fact preference into an operating system
for AI-assisted design—and where human judgment still matters.

## Story

1. AI design fails through convergence: plausible outputs repeatedly settle on recognizable defaults.
2. Impeccable changes the decision structure, not merely the styling.
3. Version 4.0 adds two decisive mechanisms: visual Worlds and a smoother Live Mode.
4. Worlds expand the option space before commitment; variants explore within the chosen world.
5. This creates a two-level loop: macro direction first, micro refinement second.
6. Live Mode makes local iteration visual: select, request, compare, tune, accept.
7. The terminal remains the correct tool for sweeping changes; Live Mode owns component-scale changes.
8. Detection and DESIGN.md convert taste into reusable rules and quality checks.
9. A fresh-context finish review protects the build from drifting back to default patterns.
10. Outside references can reset the direction when the chosen world is wrong.
11. The trade-off is real: a general system has a lower floor than a one-trick style skill, but a much higher ceiling.
12. The practical conclusion is an operating model: brief → worlds → select → build → live iterate → detect → record → review.

## Source discipline

All claims come from the supplied transcript. Screenshots appear only to prove Worlds, Live Mode,
and reference-driven redirection. The remaining slides are native, editable synthesis.
