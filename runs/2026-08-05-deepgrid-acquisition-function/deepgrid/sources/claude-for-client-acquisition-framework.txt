              Claude For Client Acquisition
              The 10 levels of automation, and how to unlock each
              one.
              Most people use Claude like a vending machine. Ask, get, leave. Then they wonder why
              nothing in their business actually changed.
              Getting clients is a machine with parts: find people, pick the good ones, talk to them,
              book them, close them, onboard them. Each part can be automated. But you can’t
              automate part 6 if part 1 is still a mess in your head.
              So this is a ladder. Level 1 is one prompt. Level 10 is your whole acquisition function
              running while you sleep. Every level below has the actual build steps, not vibes.


              Read this first (30 seconds)
              Rule 1 — Don’t skip levels. Level 7 built on a broken Level 3 is just a faster mess.
              Rule 2 — Automate what you’ve done by hand 10 times. If you’ve never written a
              cold email that worked, you can’t teach a machine to write one. You’ll just scale bad.

              Level 1 — The Saved Prompt
              Explained like you’re 2 years old: you write one really good instruction, save it, and
              use it forever instead of retyping it badly every time.
              What you get: one repeated task stops eating your day.
              Build time: 20 minutes.
              Most people’s prompts are bad because they’re vague. “Write a cold email for my
              agency.” That gets you cold email soup. A good prompt has four parts and nothing
              else.

              Build it
                  1. Pick your most repeated writing task. Follow-up emails, DM replies, call recaps.
                     Pick the one you do most, not the one that sounds coolest.
                  2. Do it manually one more time. Keep the version you’d actually send. That’s your
                     gold standard.

                  3. Write the prompt using the four-part structure below.
                  4. Test it three times with three different real inputs.
                  5. Compare against your gold standard. Fix the prompt, not the output. If you’re
                     editing the output every time, the prompt is wrong.
                  6. Save it somewhere you’ll find it in 10 seconds.

              The four-part structure

                    ROLE You write follow-up emails for [your company], a [what you do] for [wh
                    o you serve]. INPUT Here are my notes from the call: [paste raw notes] OUTP
                    UT One email. Under 120 words. Subject line included. Structure: one line o
                    n what they said, one line on the exact problem, one line on what we'd do,
                    one clear next step with a date. RULES - Plain English. No "I wanted to rea
                    ch out" or "circle back". - No compliments about their company. - One ask o
                    nly. - Write like a person who has done this 400 times, because I have.




              Done when: you can paste raw input, hit enter, and send the result with zero edits 8
              times out of 10.
              Move up when: you notice the task actually has multiple steps and you keep
              prompting three times in a row to finish it.


              Level 2 — The Chain
              Explained like you’re 2 years old: one job, but four instructions in a row, where each
              answer becomes the next question’s food.
              What you get: jobs that used to take an afternoon take 15 minutes.
              Build time: 1 hour.
              A cold outreach round isn’t one task. It’s: find who, work out what they care about,
              pick an angle, write it, then write the follow-ups. Trying to do that in one prompt gives
              you generic mush because Claude has to guess at every step at once.

              Build it
                  1. Write down the job as steps on paper. Literally number them. If you can’t, you
                     don’t understand the job yet.
                  2. Turn each step into its own prompt using the Level 1 structure.

                     step can use it.
                  4. Run them in a single chat, in order, one message at a time.
                  5. Add a checkpoint. After step 2, you read it and approve or correct before moving
                     on. This is where quality comes from.

              The six files (write these once)
                  •    01-offer.md — What you sell. What it costs. What’s included. What’s not. What
                    the client has to do. Typical result and typical timeline. Be specific with numbers.

                  • 04-proof.md — Case studies, numbers, names you’re allowed to use,

                  • 06-process.md — What happens from first contact to signed. Every step, who
                    does it, how long it takes.

              Level 4 — The Skill
              Explained like you’re 2 years old: a skill is a folder you hand Claude that says “when
              this kind of job comes up, here’s exactly how we do it here.” It picks it up on its own.
              What you get: a job runs the same way every time, whoever runs it, wherever they run
              it.
              Build time: 2 hours for your first one, 20 minutes after that.
              A prompt is something you remember to use. A skill is something Claude reaches for
              automatically when the task matches. That’s the difference, and it’s a big one.
              A skill is a folder with a SKILL.md file in it. Plain markdown. You can add templates,
              checklists and scripts alongside it. Claude only loads it when it’s relevant, so you can
              have loads of them without slowing anything down.
              Available on paid plans. In Claude, add them in settings. In Claude Code, drop the
              folder in ~/.claude/skills/ for personal or .claude/skills/ for a project.

              Build it
                  1. Pick a job you’ve now run 10+ times at Level 2 or 3. Lead research is the best first
                     one for acquisition.
                  2. Ask Claude to use the skill-creator skill. It interviews you and builds the folder. Or
                     write the file yourself using the template below.
                  3. Write the description line carefully. This is the only bit Claude reads when
                     deciding whether to use the skill. Vague description, skill never fires.
                  4. Add your templates and checklists into the same folder.
                  5. Upload it, then test by describing the task in normal language without naming the
                     skill. If it doesn’t trigger, your description is too vague.

              Level 9 is separate machines. Level 10 is a system: one shared source of truth, one path
              a lead travels, defined handoffs, defined human checkpoints, and a feedback loop that
              improves it.
              You are not removed from this. You’re moved to where you’re actually worth
              something: the calls, the judgement calls, and the exceptions.

              The five pieces
              1. One source of truth. A single folder or database every agent reads and writes. Every
              lead is one record. Every record has a state: new → researched → contacted → replied
              → booked → proposed → won / lost / dead . If two agents disagree about what state a
              lead is in, your system is broken. This is the foundation. Get it wrong and nothing
              above it works.
              2. One intake path. Every lead enters the same way regardless of source — referral,
              inbound, cold, event. Same record shape, same first step. Multiple intake paths is the
              number one reason these systems collapse.
              3. Agents on stages, not tasks. Each stage of the pipeline has one agent that owns it,
              and one artifact it produces to move a lead to the next stage.
              4. Human checkpoints, written down. Decide in advance where a person must touch
              the work. Suggested minimum: anything sent to a client, any price, any contract, any
              lead scoring above 9, anything the Auditor failed twice.
              5. A feedback loop. Weekly, an auditor agent reads the logs and reports: where leads
              died, which emails got replies, which scoring rules were wrong, what humans had to
              fix. You change one rule per week based on it. One. Change five and you’ll never know
              which one worked.

              Build it
                  1. Map the current reality. Every step from stranger to onboarded client, as it
                     actually happens, including the ugly manual bits. Time each step.
                  2. Pick the state model. Write the list of states. Get this right before anything else.
                  3. Define the artifact per stage. Research brief. Outreach thread. Call brief. Proposal.
                     Onboarding pack. Each one is a file with a fixed shape.

                  4. Assign an agent per stage. Reuse your Level 8 team. Add Onboarder.
                  5. Wire the triggers. State change fires the next agent. Time-based schedules handle

                  6. Write the exception rules. What stops the machine and calls you. Be generous
