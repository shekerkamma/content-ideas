# Beacon.li Competitor Analysis Story / Structure Review

Date: 2026-07-14

## BLUF

The current Beacon.li deck is comprehensive, but it is not yet structured like a rigorous competitor-analysis readout. It is closer to a research-backed positioning pack with competitor modules appended over time.

## Audience Decision

The reader should be able to decide:

1. What category Beacon should compete in.
2. Which competitors matter most.
3. Where Beacon wins and loses by evaluation dimension.
4. What proof is required before investing in the positioning.
5. Which response moves sales/product/marketing should execute next.

The current deck lands 1, 4, and 5 reasonably well, but 2 and 3 are under-structured.

## What Works

- The core thesis is strong: Beacon should be positioned as implementation execution, not as a generic DAP.
- The competitor universe is broad enough: DAP, onboarding/implementation ops, enterprise AI delivery, automation, and consultancies.
- The source trail is present and separated into run artifacts.
- The deck includes important building blocks: competitor matrix, quadrant, pricing/funding signals, battlecards, POC scorecard, buyer map, source confidence, consulting-firm war game.
- The consulting-firm add-on materially improves the strategic context.

## What Does Not Work Yet

### 1. The storyboard is additive, not architectural

The deck grew in layers:

1. Core Beacon vs DAP/onboarding/AI positioning.
2. Expanded battlecards and proof plan.
3. Consulting-firm add-on.

Those modules are valuable, but the slide order shows the build history. The deck now has multiple "next move" or "recommendation" moments before the analysis is complete.

### 2. The evaluation rubric appears too late

The rubric and job-to-be-done matrix appear after early recommendations. In a structured competitor analysis, the rubric should appear before competitor comparisons and become the backbone for every subsequent slide.

### 3. Competitor analysis is not consistently scored

The current deck says where competitors win and lose, but does not apply one stable scoring model across all vendors. A client cannot quickly compare WalkMe, Rocketlane, Unframe, UiPath, and Accenture on the same dimensions.

Missing structured scoring dimensions:

- implementation execution depth
- enterprise trust
- system-of-record fit
- workflow specificity
- proof quality
- distribution strength
- pricing transparency
- threat severity
- partnerability

### 4. The consulting-firm section is currently an appendix

The consulting section is strategically important, but because it appears near the end, it reads like a late add-on. It should either be:

- folded into the main competitor universe as a fourth competitive arena, or
- explicitly labeled as an appendix / strategic extension.

Right now it is neither fully integrated nor clearly appendix-only.

### 5. Layout quality is acceptable but too dense for executive consumption

The slides pass QA and no longer show overflow, but many slides use the same three-card/six-card pattern. This makes the deck feel comprehensive but repetitive. It needs more varied visual systems:

- one master market map
- one scored competitor heatmap
- one threat-priority matrix
- one buying-committee map
- one strategy decision tree
- one action roadmap

### 6. Skill piping was incomplete

The work used several skills, but not in the optimal sequence. The biggest miss was running deck-building before a formal story-architecture pass.

Correct sequence should have been:

```text
GBrain Recall
→ Firecrawl / Exa / content-research
→ enterprise-ai-competitor-landscape
→ competitive-intel-sprint
→ strategy-consulting / competitive-intel
→ strategy-consulting / war-gaming
→ ai-transformation / build-buy-partner
→ story-architect
→ branded-pptx-deck
→ officecli-qa + Playwright QA
→ GitHub Pages publish
→ GBrain / memory write-back
```

The actual sequence was closer to:

```text
Research
→ competitor landscape
→ deck
→ user critique
→ grill-me expansion
→ consulting expansion
→ QA / publish
```

That explains why the final artifact has good content but a weaker argument spine.

## Recommended Storyboard Rebuild

### Section 1 — Executive Answer

1. Cover
2. BLUF: Beacon should own implementation execution, not DAP or generic AI transformation
3. Decision map: where Beacon competes and what must be proven
4. Methodology: source route, competitor universe, scoring dimensions

### Section 2 — Market And Competitor Universe

5. Market map: four arenas
   - DAP
   - implementation operations
   - enterprise AI / automation
   - AI transformation consultancies
6. Job-to-be-done matrix
7. Evaluation rubric
8. Competitor universe table

### Section 3 — Scored Competitive Assessment

9. Scored heatmap across all vendors
10. Threat-priority matrix
11. Where Beacon wins
12. Where Beacon loses
13. Proof gaps and confidence levels

### Section 4 — Category-by-Category Deep Dive

14. DAP category diagnosis
15. WalkMe/SAP battlecard
16. Pendo / Whatfix / Appcues comparison
17. Implementation operations diagnosis
18. Rocketlane battlecard

### Section 6 — Proof And Action Plan

33. POC scorecard

## Rebuild Instructions

1. Reduce deck from 54 slides to roughly 36-40 slides.
2. Move the methodology, rubric, and job-to-be-done matrix into the first 8 slides.
3. Convert the competitor matrix into a scored heatmap.
4. Treat consulting firms as a fourth arena, not a late appendix.
5. Keep battlecards, but standardize each to the same layout:
   - when it appears
   - why it wins
   - where Beacon wins
   - where Beacon loses
   - proof needed
   - sales response
6. Make one final recommendation slide only, near the end.
7. Convert repeated card slides into fewer, stronger tables and diagrams.
8. Keep source confidence, but move detailed source lists to appendix/HTML.

## Final Judgment

This is not a failed competitor analysis. It is a strong research pack that needs a storyboard rebuild to become a disciplined competitor-analysis deck.

The right next step is not more research. It is a structural rebuild using the existing research into a stricter competitor-analysis spine.
