Advanced · Harness Engineering

The RALF Loop

Multi-session orchestration for large tasks — deterministic, not chaotic

SESSION 01
PLANNER
Reads the full spec. Defines phase list. Creates detailed task handoff document.
→ handoff.md
→
SESSION 02
IMPLEMENTER
Reads handoff. Executes phase. Stays in clean context. One phase at a time.
→ execution-report.md
→
SESSION 03
VALIDATOR
Reads execution report. Runs code review. Validates outputs against spec.
→ ships ✓
Why RALF?
One Claude Code session cannot handle a large task without hitting the dumb zone (250K tokens). RALF loops break work into fresh-context sessions, each with a clean handoff doc.
Archon Project
Cole's open-source project building deterministic multi-agent session orchestration on top of Claude Code. Assembly line for AI agents.
"Build Claude Code into a system instead of having Claude Code trying to orchestrate everything. Pick when the AI model works — don't let it drive the whole thing."
Security

The Security Mindset

Prompts are not a permission layer — infrastructure is

⚠ False Security
  • "Never wipe the database" → it still will
  • "Don't delete the folder" → it writes a script that does
  • Prompt instructions are not enforced at runtime
  • Proactive agents will touch anything readable
Real incident: Agent misread a task list and sent a discount email to an entire customer list.
✓ Real Protection
  • Scoped API keys (read-only, limited write)
  • Infrastructure-level permissions, not just prompts
  • Assume: anything readable or touchable, it WILL touch
  • Security is part of the verification pipeline
"Anything that the agent can read or touch, you have to assume that it will — even if you never ask it to."
Vibe Coders Get Burned Supabase keys leaked in JS · databases wiped · emails sent · API quotas blown
Security = Part of Verify Include secret scanning, env var checks, and permission audits in your validation pipeline
