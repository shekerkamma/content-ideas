# Content Research: Multifamily Leasing & Resident Communication Automation

## Source set

1. Local PDF: `Ai Engineering Use Cases Framework Document.pdf`
2. AppFolio Realm-X official product materials
3. Yardi CRM IQ / leasing workflow materials
4. Docusign AI / Agreement AI materials
5. OpenHands GitHub and docs
6. Greystar official site for operating-scale context

## Why this use case

- The PDF's real-estate section explicitly names lease generation and marketing automation as AI use cases, which makes leasing workflow automation a direct continuation rather than a fabricated adjacent idea.
- Multifamily operators have clear revenue exposure to response-time drag, vacancy delay, incomplete applications, and renewal leakage.
- The workflow is operational enough to support AI services, but visible enough to show ROI quickly.

## Source notes

### 1. Framework-document signal

- Section: real estate
- Explicit use cases in the source material include lease generation, marketing automation, and CRM-specialist style workflows.
- Why it matters: the third run stays anchored to the original framework instead of drifting into a different vertical.

### 2. AppFolio signal

- URL: `https://www.appfolio.com/realm-x`
- AppFolio positions Realm-X for leasing workflows such as always-on response, follow-up support, and workflow assistance around the prospect funnel.
- Why it matters: incumbent software is already packaging AI as a teammate embedded inside property workflows.

### 3. Yardi signal

- URL: `https://www.yardi.com/products/crm-iq/`
- Yardi markets CRM and leasing workflow capabilities around lead capture, engagement, and centralized visibility.
- Why it matters: the problem is already productized in enterprise real-estate software, which validates buyer awareness.

### 4. Docusign signal

- URL: `https://www.docusign.com/ai`
- Docusign markets Agreement AI and agentic agreement workflows that fit lease packets, renewals, and resident-document execution.
- Why it matters: document automation is a realistic phase-two expansion path after leasing response and routing.

### 5. OpenHands signal

- URLs:
  - `https://github.com/OpenHands/OpenHands`
  - `https://docs.openhands.dev/`
- Verified fit:
  - SDK agents for reusable orchestration
  - skills and repository agents for leasing-policy logic
  - CLI/headless operation for repeatable workflow runs
  - MCP/server connectivity patterns for tool integration
- Why it matters: use OpenHands internally as the execution layer instead of hand-building bespoke automation for each operator.

### 6. Greystar operating-scale signal

- URL: `https://www.greystar.com/`
- Greystar represents the kind of scaled operator where centralized leasing, service, and renewal workflows can compound operational savings.
- Why it matters: the pitch can target real operators, not just software vendors.

## Synthesis

- Best wedge: prospect-response and renewal workflow automation inside the PMS/CRM stack.
- Best expansion: lease packets, resident messaging, service coordination, and renewal execution.
- Buying motion: start with a single regional portfolio or centralized leasing team, prove faster response and cleaner handoffs, then expand into document-heavy workflows.
- OpenHands fit: orchestration for reusable leasing, renewal, and resident-service workflow agents.
