Eve’s move:  keep the ease of the folder — put the production layer in the box. The trade-off is gone.

The Agent Is a Directory
EVE // OPS BRIEF / The Agent Is a Directory 04 / 13
Model  ·  Convention over configuration
Each capability is a file at a known path.
agent/  —  source of truth
agent/
├── instructions.md            # always-on prompt
├── tools/
│   ├── run_sql.ts             # => tool "run_sql"
│   ├── list_orders.ts
│   └── post_to_slack.ts
├── skills/
│   ├── refund-policy.md       # on-demand playbook
│   └── sql-style-guide.md
├── subagents/
│   └── reviewer.ts            # own context
└── channels/
    ├── http.ts
    ├── slack.ts
    ├── discord.ts
    └── github.ts
instructions.md
Always‑on system prompt
The agent’s identity, rules and defaults — one Markdown file.
tools/*.ts
One typed TypeScript function per file
Filename becomes the tool name. run_sql.ts ⇒ tool run_sql. Nothing to register.
skills/*.md
Markdown playbooks, loaded on demand
Domain knowledge kept out of the base prompt — pulled in when it’s needed.
subagents/*.ts
Child agents with their own context
Delegate scoped work — a reviewer, a planner — without polluting the parent’s window.
channels/*.ts
Entry points: HTTP · Slack · Discord · GitHub

Production In The Box
EVE // OPS BRIEF / Production In The Box 06 / 13
Runtime · Deploy
The reliability layer ships with the framework.
01 · Durable sessions
Checkpointed workflow — survives crashes and redeploys.
Restarts resume exactly where they stopped. Long-running agents stop being fragile.
02 · Vercel Sandbox
Agent‑written code runs isolated — off your machine.
Untrusted code stays in a controlled runtime, not your laptop or a shared shell.
03 · Approvals
Human-in-the-loop, native.
Risky tool calls pause and wait for a human Allow. Built in, not bolted on.
04 · Evals
Deploy gate, not an afterthought.
Evals sit on the deploy path. Regressions stop the release before users see them.
05 · One deploy
vercel deploy — live over HTTP & Slack.
Same directory, prod.
Net:  the operational surface an internal team actually needs — delivered as defaults, not homework.

NO HEDGING — JUST THE TWO LEDGERS Slide 11
The Move
EVE // OPS BRIEF / The Move 12 / 13
Playbook
Pilot the pattern on one bounded workflow.
Clear owner. Slack surface. Rules encoded as skills. Risky calls gated by approvals and evals.
01
Pick
One bounded internal workflow.
Clear owner. Real users. Slack as the surface. Not a customer-facing agent — yet.
02
Build
Instructions + typed tools + one skill.
instructions.md  +  a few tools/*.ts  +  one skills/*.md. Let the plugin scaffold.
03
Encode
Rules that must stay consistent → Markdown.
Refund policy, SQL style, escalation path. One .md per rule — readable, review-able, diffable.
04
Gate & widen
Approvals + eval suite before widening access.
Risky actions require a human click. An eval suite blocks regressions on deploy. Then open the door.
Ship a pilot in weeks, not a platform in quarters.
