# Skill Doctor

Find skill files that survived as filenames but lost their contents, then restore
them from the best available donor. Report first, write second.

State at invocation:

> Auditing skill trees for zero-fill corruption. Report-only unless you ask me to apply.

## When this applies

Zero-fill corruption leaves a file at its original size with every byte NUL. The
directory listing looks correct, `ls -l` shows a plausible size, and the skill
still appears installed — it simply does nothing. A failed WSL VHDX migration is
the known cause on this machine; any interrupted disk copy produces the same shape.

Three distinct damage patterns exist, and only the first is visible to a
contents check:

1. **Nulled files** — present, all-NUL.
2. **Empty directories** — the directory survived, its files did not.
3. **Never-copied files** — absent from the live tree, present with content in
   the source that was being copied from.

A scan that only matches NUL bytes is structurally blind to (2) and (3). For
those, compare *path sets* between the live tree and the source, and copy only
where the live target is absent.

## Run it

```bash
# report only (default) — scans every */skills/* tree under the given roots
python3 scripts/audit_skill_corruption.py ~

# include git history as a donor source
python3 scripts/audit_skill_corruption.py ~ --git-repo /path/to/repo

# write the restorations
python3 scripts/audit_skill_corruption.py ~ --git-repo /path/to/repo --apply

# show suppressed noise (bytecode, caches, backups)
python3 scripts/audit_skill_corruption.py ~ --include all
```

Exit status is non-zero when a **live** skill file is corrupt with no donor —
suitable as a CI or preflight gate. Bytecode, caches, and backups never affect it.

## Donor ranking

Take the first that yields healthy content:

1. **Same skill under a sibling host root** — `.claude/skills/`, `.codex/skills/`,
   `.agents/skills/`, `.github/skills/`, and repo `skills/`. Matched on
   `(skill_name, path_within_skill)`, never on basename alone.
2. **Git history** — `git log --all` then `git show <commit>:<path>`. This
   survives working-tree corruption completely and is often the *only* source
   for files deleted from the tree in a later refactor.
3. **A rescue/salvage extraction**, if one exists. Expect it to share the same
   damage, since the live tree usually descends from it.

## Rules

- **Never overwrite a healthy file.** Write only where the target is confirmed
  all-NUL.
- **Never copy a NUL or zero-byte donor.** Verify the donor before writing.
- **Never match donors on basename alone.** A single `SKILL.md` copied over a
  dozen unrelated `SKILL.md` files is silent, wide corruption. Require the full
  path within the skill to match, or prove the basename is unique on both sides.
- **Do not write through symlinks.** Many host skill entries are symlinks into a
  repo; `find` does not traverse them, so a "0 files" result proves nothing.
  Writing through one clobbers the repo.
- **A zero-byte file is not corrupt.** `b"".strip(b"\x00")` is `b""`, so any
  naive check flags every empty file. Guard on size first.
- **Prefer a copy over a re-clone.** Re-cloning a repo destroys local-only
  content — nested projects, `settings.local.json`, and `.agents/`/`.cursor/`
  harness ports live only in the working tree. Checking for `.env` is not enough.
- **An additive restore can still break a rebuild path.** Partially refilling a
  directory defeats any `if [ -d "$target" ]; then skip` guard. After restoring
  into a tree that a build script populates, confirm the script no longer skips it.

## What is out of scope

Generated bytecode (`__pycache__`, `*.pyc`), plugin caches, and dated backup
directories are classified and suppressed by default. They regenerate, re-download,
or are superseded by whatever they were a backup of. Do not spend recovery effort
on them, and do not let them inflate a corruption count.

When a skill is published upstream under a permissive license, re-fetching the
release is cheaper and more correct than reconstructing it locally. Check
`SKILL.md` frontmatter for `license` and `metadata.author` before concluding a
skill is unrecoverable.

## Success criteria

- Every corrupt file is classified `live`, `backup`, `cache`, or `bytecode`.
- Every `live` file either restored, or named with the reason no donor exists.
- No healthy file overwritten; no NUL donor copied.
- Re-scan returns zero fixable `live` files.
