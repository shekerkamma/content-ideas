# Accenture analytical grammar

## Core sentence grammar

Use answer-led titles:

```text
[Actor / market] should [decision] because [causal mechanism], while [boundary or risk]
```

Other valid forms:

```text
[Evidence] indicates [bounded conclusion]—not [overclaim]
[Competitor] threatens [control point] through [mechanism], but [proof boundary]
[Option] wins only if [observable condition]; otherwise [stop rule]
[Market shift] changes [decision] from [old posture] to [new posture]
```

Avoid topic labels such as “Competitive landscape,” “Starkenn overview,” or “Recommendations.”

## Page logic

Each page must contain this chain:

```text
question → evidence → analytical operation → conclusion → implication → decision/trigger
```

The analytical operation must be explicit: compare, segment, prioritize, decompose, bridge, test,
qualify, sequence, or falsify.

## Comparison grammar

- Define the comparison universe and buyer context.
- Compare on control points: award access, system accountability, integration readiness, proof,
  economics, channel leverage, service, or regulatory gate.
- Use like-for-like scope. Do not compare a perception module with a full AEBS system without
  separating stack layers.
- Show confidence and evidence gaps beside the conclusion.

## Recommendation grammar

Write recommendations as:

```text
Move: [bounded action]
Why now: [evidence-backed urgency]
Owner: [role]
Done when: [observable completion]
Escalate when: [signal]
Stop when: [falsifier or failed gate]
```

## Competitor dossier grammar

Use a consistent sequence for comparable companies:

1. bounded profile and operating scope;
2. segment-by-segment threat mechanism;
3. evidence/proof ledger;
4. control-point collision with the client;
5. advantages that survive the comparison;
6. partnership/channel option;
7. counter-moves and diligence gates.

Do not let repetition become template filler: maintain the comparable geometry while changing the
evidence, conclusion, and mechanism.
